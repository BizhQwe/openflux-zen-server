# Совместимость и перенос функций

Исходник: локальная копия OpenFlux из бывшего `D:\Projects\openflux-web-panel`. Референс панели: бывший `D:\Projects\openflux-zen-server`, Zen Server 1.1.1 на .NET. Обе старые папки сохранены с суффиксом `-legacy`.

## Ядро

Текущая база — официальный [OpenFlux v0.13.0](https://github.com/p1neappleXpress/OpenFlux/releases/tag/v0.13.0), commit `4f9c786cdd1d9fcd0c133e2e0fec0c5a12522610`. Полный аудит локальных патчей, перенесённые возможности, параметры новых транспортов и ограничения совместимости описаны в [отчёте миграции](../../../docs/core-upgrade-v0.13.0.md). Одиночные старые каналы сохраняют wire v2/legacy; новым группам нужен Striped на обеих сторонах. Bitrix24 использует собственную авторизацию клиента.

Сохранены прежний module path `github.com/p1neappleXpress/OpenFlux`, зависимости и файловая структура внутри проекта ядра. Исключены три macOS-файла utun; в main.go добавлены ограничение Windows/Linux и сообщение об управляемой защите L3. В Linux raw-backend добавлена необязательная локальная SO_MARK из окружения панели: она позволяет Go/netlink подавлять RST только для TCP-соединений туннеля. При запуске ядра отдельно без этой переменной поведение исходного OpenFlux сохраняется. Веб-панель запускает отдельный процесс ядра через его исходные CLI-флаги; протоколы, шифрование, кодеки и wire negotiation не изменены.

IPC-фрейминг и QR/ссылки используют непосредственно пакеты `transport/ipc` и `share` ядра. Ссылка создаётся самим ядром после готовности транспорта; панель не изобретает собственного формата подключения. Поддержка Android/iOS и мобильные сборочные файлы удалены из нового проекта; пакеты для Windows/Linux собираются с CGO_ENABLED=0.

Allowlist типов в share-формате совпадает с оригинальным v0.13.0. Mixed не включается в ссылку/QR: официальный декодер его отвергает, хотя registry ядра поддерживает ручную настройку группы. В версии 1.1.2 пояснение удалено из формы по запросу пользователя; правила экспорта сохранены. В Multi экспортируются только поддерживаемые каналы. При выключенном строгом согласовании обычный Multi сохраняет штатный classic fallback апстрима; Direct и Script требуют Session. При миграции ядра проверены ссылки в обе стороны с чистым ядром v0.13.0 и настоящий TCP-обмен с ним через SOCKS5. Статус повторной проверки для 1.1.2 указан в [листке валидации релиза](../../../docs/releases/v1.1.2-validation.md).

В JSON статуса IPC добавлено необязательное поле `peer_status`; прежнее `connected` и фрейминг сохранены. Наличие клиента определяется ответами на существующие ping/pong, без новых сетевых сообщений. Комната транспорта может оставаться открытой после ухода клиента, но больше не обозначается клиентским подключением. В обычной сессии отсутствие ответов обнаруживается примерно за 15 секунд; в classic без heartbeat показана недавняя активность, точное присутствие не заявляется. Отсутствие IPC более 4 секунд сбрасывает текущую скорость и присутствие, после восстановления соединения статистика возобновляется.

Добавлен необязательный флаг `--telemost-url` для собственного URL Телемоста в Multi. Формат cookies и IPC CookiesOffer не изменён: выбор транспорта в окне Multi заполняет существующее поле Transport и не затрагивает cookies остальных транспортов. Передаваемая в QR строка совпадает с исходной ссылкой; PNG создаётся с целыми пикселями на модуль, стандартным белым полем и исходным масштабом от 1024 px.

Cookies остановленного туннеля можно сохранить без IPC и без запуска процесса. Панель атомарно записывает их в существующий файл `data/cookies/<id>.json` с правами 0600. JSON остаётся картой ключей с jar; новые записи имеют ключ `transport:<type> <original-session-key>`, поэтому автоматические комнаты Avito и Cups.online с пустым URL получают разные cookies. Ядро загружает такую запись до Start транспорта; при её отсутствии использует прежний ключ URL/скрипта. Старые jar и остальные транспорты сохраняются. Новые cookies объединяются с уже сохранёнными, а повреждённый файл не перезаписывается. Работающий процесс получает cookies по прежнему IPC; внешняя запись поверх его живого хранилища не выполняется.

## JSON предыдущей панели

`api/config/import` принимает старую обёртку `{Version, ExportedAt, Tunnels}` либо массив туннелей. Имена полей с PascalCase и camelCase читаются одинаково. Сохраняются параметры CLI, ключи, ID и известные поля туннеля. Новые туннели импортируются остановленными; обновление включённых существующих туннелей вызывает их перезапуск.

Переносите старые туннели через экспорт/импорт. Старые `settings.json`, plaintext credentials, сессии и .NET-бинарники не копируются в новый каталог данных. Панель создаёт собственные учётные данные; старые логины/пароли не мигрируются.

Панель принимает и запускает только `role=exit`. JSON-поля прежнего формата сохранены, но роли client/bench-send/bench-sink и дополнительные аргументы, меняющие роль (включая -r и устаревшие флаги), отклоняются. Ранее сохранённые несовместимые профили остаются в данных, отключаются и не запускаются при восстановлении; их можно исправить или удалить через панель. Запись без роли из старого серверного хранилища получает exit. Формат подключения клиентов не изменён: клиенты используют отдельное приложение/CLI OpenFlux.

## Что изменилось

Веб-интерфейс восстановлен из старого проекта. Сохранены оформление, логотип и транспортные иконки; у Avito добавлено скругление, шрифт заменён на Segoe UI / системный sans-serif и Consolas / Liberation Mono для кода, без загрузки Google Fonts. HTML лежит в `web/html`: общий index, пять страниц в pages и четыре модальных окна в dialogs. JavaScript сгруппирован в common/pages/vendor. Изображения перенесены в плоскую `web/images`; дубликат yandex-telemost удалён. Go собирает фрагменты при запуске. По запросу пользователя удалено предупреждение L3, в окне cookies добавлен выбор транспорта Multi, QR увеличен и дополнен скачиванием PNG. Кнопки «Скачать PNG» и «Закрыть» имеют одинаковую высоту 40 px. Обработчики и переводы заглушек удалены. Демо-данные в поставку не включены.

При первой установке и явной регенерации секретного пути создаётся 18 криптографически случайных букв и цифр с равномерным распределением, без префикса и спецсимволов. Обновление сохраняет старый путь, в том числе прежние `zen-...` адреса; регенерация меняет маршрут и завершает старые сессии.

| Возможность старой панели | Новая реализация |
|---|---|
| Туннели, процессы, восстановление | Go-супервизор; ограниченные повторные попытки запуска |
| Логи и трафик | IPC ядра, текущая скорость в двух колонках, общий трафик отдельно, остановка по лимиту |
| Ссылки и QR | Исходная ссылка ядра без изменения формата, чёткий PNG и скачивание |
| Авторизация / cookies / SmartCaptcha | Сохранение cookies до запуска; загрузка перед подключением, либо передача через IPC без перезапуска; проверку выполняет пользователь |
| LAN / домен | Рабочие переключатели и отдельный порт панели; домен без схемы использует её HTTP/HTTPS и порт, полный URL сохраняет адрес существующего reverse proxy. DNS/proxy настраиваются отдельно |
| Localtunnel | Встроенный Go-клиент по [протоколу официального клиента](https://github.com/localtunnel/localtunnel/blob/master/lib/Tunnel.js); включение через веб/установщик, статус соединения и публичный URL |
| Zrok / ACME | Zrok не перенесён. Go-выпуск Let's Encrypt через --issue-tls с временным HTTP-01 на свободном 80; автоматическое продление собственных сертификатов. Готовые PEM также поддерживаются |
| Обновление / rollback .NET-панели | Повторный запуск цельного установщика этой версии/нужной предыдущей версии; JSON-данные сохраняются |
| Обновление скриптовых транспортов | Исходные флаги script-auto-update, stable/nightly сохранены |
| Точное количество/лимит клиентов | IPC ядра отдаёт connected как bool; точный счётчик/лимит не заявляется. Ненулевой clientLimit отклоняется при валидации |
| Системные CPU/RAM метрики | Реальные счётчики Windows GetSystemTimes/GlobalMemoryStatusEx и Linux /proc/stat, /proc/meminfo; загрузка CPU вычисляется по разнице замеров |
| Языки | Исходные RU/EN тексты и переключатель; выбранный язык сохраняется |
| Служба / установка | Systemd на Linux, Task Scheduler на Windows; цельный установщик с тремя Go-бинарниками, глобальная команда openflux |
| CLI | Справка в прежнем оформлении: start/stop/restart/status, autostart, credentials, полное uninstall и help. Настройки network/reset удалены из CLI |
| Пароль в CLI | Логин, действующий пароль и ссылки. PBKDF2 для авторизации; отдельный защищённый локальный файл для показа. Старый hash-only пароль запрашивается и проверяется один раз при обновлении |
| Удаление | openflux uninstall проверяет маркер установки и принадлежность службы, удаляет бинарники и собственную регистрацию команды; полностью удаляет данные вместе с программами |
| Заглушки / decoy | Полностью удалены по запросу пользователя. Вне секретного пути — 404; API и команды decoy нет |

Встроенная страница авторизации скрипта (HTML) и удалённый captcha proxy не проксируются веб-панелью: собственную страницу скрипта открывают на сервере, удалённую проверку — через proxy, указанный IPC. Автоматическое решение пользовательской SmartCaptcha не добавляется.

Пакеты Wintun/WinDivert и драйверы не загружаются автоматически. Это отдельные платформенные компоненты оригинального ядра. Windows L3/TUN использует компоненты ядра; L4/SOCKS5 работает без этих DLL. Linux L3 дополнен автоматической защитой RST по адресам и портам соединений через встроенный Go/netlink-клиент nftables. Внешняя команда nft не нужна; ядро Linux должно поддерживать используемые nftables-наборы.

CLI и панель используют общий пакет configuration: один формат settings.json, прежний PBKDF2, атомарная запись и межпроцессная блокировка. credentials читает данные без изменения настроек. Полное удаление останавливает службу и берёт общую блокировку; работающую панель без службы сначала нужно остановить вручную. Обычный installer также проверяет блокировку перед обновлением файлов.

Бинарники названы по проектам: openflux-zen-server-core, openflux-zen-server-web и openflux-zen-server-cli, с .exe на Windows. Установщик обновляет установки с прежними именами, удаляя только известные старые бинарники и сохраняя data. Команда openflux сохраняется: symlink в /usr/local/bin и /usr/bin на Linux, openflux.cmd на Windows. Имена существующей systemd-службы и Windows-задачи сохранены.

Консольный мастер воспроизводит старое оформление: язык, размещение, автозапуск, три шага и карточка доступа. Режимы LAN/localhost меняют listen, Localtunnel включает встроенный Go-клиент, домен задаёт адрес reverse proxy. Без терминального ввода и с --silent существующие настройки сохраняются, кроме явно заданных параметров. На Linux WorkingDirectory больше не заключён в кавычки; установка заменяет ошибочный unit и перезагружает конфигурацию systemd. Запуск службы и проверка готовности отделены от её регистрации; сообщение об успешном запуске требует ответа панели.

Временная таблица Linux L3 имеет имя, зависящее от каталога данных. Перед удалением проверяются журнал и метки владельца всех правил. Чужие таблицы и весь ruleset не очищаются. Отсутствие CAP_NET_ADMIN или поддержки nftables вызывает понятную ошибку запуска; неработающий L3 не обозначается успешно запущенным.

## Трафик и System

Новые необязательные IPC-поля `traffic_bytes_in`/`traffic_bytes_out` считают IPv4-пакеты до сжатия и шифрования во всех управляемых L3/L4/Multi туннелях. Старые `bytes_in`/`bytes_out` остаются счётчиками транспортного носителя. Пакеты и share-ссылки не меняются; прежние клиенты совместимы. Служебные сообщения не добавляются в IP-трафик. Объём включает заголовки и повторные TCP-передачи, поэтому может превышать размер скачанного файла. Старые накопленные значения сохранены; восстановить недосчитанную историю невозможно.

Скорость рассчитывается по времени замера ядра. Повторные/устаревшие статусы не добавляют трафик. Перед остановкой запрашивается последний снимок. Переподключение IPC сохраняет базу счётчиков; старое ядро поддерживается с диагностикой об использовании carrier-счётчиков.

System записывает запуск/остановку панели и туннелей, PID, причины ошибок, IPC, состояние клиента/носителя, операции API и минутный диагностический снимок. История восстанавливается из файла; уровни INFO/WARN/ERROR/DEBUG и исходные времена сохраняются. Пароли, cookies, тела API-запросов и секретный путь не журналируются. Успешные GET-опросы не засоряют журнал; ограничения и ротация логов сохранены.

Размещение, HTTPS и совместная работа с другими панелями описаны в [NETWORK.md](NETWORK.md). Отдельная плашка доступа удалена; ссылки и обновление секретного пути находятся в блоке переключателей размещения.
