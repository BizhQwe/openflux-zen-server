# Обновление ядра OpenFlux до v0.13.0

Дата проверки: 18 октября 2026. Исходное дерево Zen Server было чистым (`cd5afe1`). База до обновления — `v0.7.3`, `f12e981629a18c8c01007d59ac002254c02972bb`. Цель — последний опубликованный релиз [v0.13.0](https://github.com/p1neappleXpress/OpenFlux/releases/tag/v0.13.0), `4f9c786cdd1d9fcd0c133e2e0fec0c5a12522610`. Ветка `main` на момент проверки старее релиза.

До замены файлов выполнено побайтовое сравнение всего встроенного ядра с архивом v0.7.3 (CRLF/LF нормализованы). Обнаружены 15 изменённых файлов и 7 локальных файлов, включая UPSTREAM.md. Для каждого изменённого файла выполнено трёхстороннее объединение local/base/v0.13.0; текстовых конфликтов не было. Локальные файлы сохранены. Перенесены:

- Windows/Linux build scope; отдельный telemost-url в Multi и регрессия его приоритета над URL из конфигурации.
- Наблюдение за живым клиентом через Session/CodecTransport/Manager, сброс Session после ухода клиента; стабильные heartbeat-тесты с виртуальными часами.
- Логические IPv4-счётчики до сжатия/шифрования, необязательные IPC-поля traffic_bytes_in/out и peer_status, запрос немедленного status и остановка status-loop вместе с IPC.
- Раздельные cookies по транспорту с обратной совместимостью ключей старого хранилища; сохранение cookies панели при остановленном ядре.
- Linux SO_MARK для адресной RST-защиты nftables и уведомление, что защитой управляет Zen Server.
- Регрессии Mail.ru batch hints, большого v2-пакета, IPv6 loopback на Windows, завершения UDP negotiation; изолированный PHP test server и обязательная проверка PHP в CI.

Сохранены прежние исключения из серверного дерева: mobile/**, ios-app/**, .github/**, .idea/**, docker/**, cmd/sharewasm/**; Dockerfile, docker-compose.yml, build_all.sh, build_android.sh, build_ios.sh, build_ios_app.sh, tun_darwin.go и корневые .dockerignore/.env.example/.gitattributes/.gitignore апстрима. Их настройки в Zen Server принадлежат собственным build/CI-скриптам. Готовый upstream-бинарник opensub-linux также исключён; его исходники включены. Новые серверные пакеты и команды, включая cmd/opensub и subscription, включены в исходники и проверяются общей сборкой/тестами; отдельный сервис подписок автоматически не разворачивается.

Добавлены и интегрированы:

- Диагностика Avito: создание комнат и первая ошибка API/сети видны при debug=0; итоговая ошибка сохраняет первопричину. Это дополнение к v0.13.0 не меняет повторы запросов и wire-формат. Проверены HTTP 403, некорректный JSON и недоступный сервер на локальных тестовых адресах.
- Bitrix24: карточка, портал, cookies, sessid, chat_id, одиночный режим и Multi; приватный файл параметров 0600 вместо секретов в argv. Исходная иконка images.png скопирована как web/images/transport-bitrix24.png (240×240); общий CSS показывает её в 28×28 с object-fit:contain и скруглением 22%, как у Avito.
- Mixed/Striped: карточка, поля typed-links и Multi. Группы одного типа включаются перечислением ссылок через запятую, | или пробел. Mixed настраивается вручную на совместимом клиенте и не экспортируется в share-ссылку: официальный декодер v0.13.0 не принимает тип mixed.
- Число auto-created lanes, Telemost stripes/stripes_max, per-carrier network, параметры lanes/lane_rooms и пользовательские script settings через JSON по типу транспорта.
- Исходящий SOCKS5-прокси в L4. L3 с таким прокси отклоняется при валидации.
- Все upstream-изменения серверного дерева: Mail.ru make-before-break rotation и pacing, 8 комнат Cups/Avito, RTO/CoDel/ACK/window-настройки Striped, Telemost health deadline, Yandex/MAX fixes, обновлённые provisioning и node pins, HTTP-прокси клиента и прочие изменения CLI.
- Новые поля сохраняются в tunnels.json и JSON-импорте/экспорте; RU/EN тексты формы. Старые записи без этих полей используют нулевые значения.

В upstream v0.13.0 отсутствует экспорт авторизации Bitrix24 через openflux://. Транспорт пропускается при генерации ссылки с пояснением, чтобы не ломать ссылки других каналов Multi и не передавать cookies сервера. Клиенту нужны собственные cookies/sessid и общий chat_id. Для новых групп обеим сторонам нужна версия с поддержкой Striped; обычные одиночные legacy/v2 каналы сохраняют совместимость. Bonding удалён апстримом: старое Bonding=yes игнорируется, Multi остаётся failover по приоритетам.

Зависимости: upstream go.mod не меняет версии библиотек относительно прежнего ядра; выполнен go mod tidy для всех четырёх модулей. Панель/CLI/Installer теперь согласованно требуют x/net 0.57.0, x/sync 0.22.0 и x/text 0.41.0; go.sum обновлены. Новые транспорты используют уже имеющиеся зависимости.

Проверки и ограничения перечислены в [VALIDATION.md](../src/OpenFlux.Zen.Server.Web/docs/VALIDATION.md). На этапе первоначальной миграции реальные внешние сервисы с пользовательскими аккаунтами не запускались; Bitrix24 проверен локальным REST-сервером, включая запуск собранного Core через CLI. Проверка --verify встроенных архивов Windows amd64/386 установщиков прошла. Изолированная браузерная проверка подтвердила сохранение Bitrix24 и Mixed, включая JSON-параметры/прокси. Итоговое обновление включено в [Zen Server v1.1.0](releases/v1.1.0.md).

## Проверка Avito и официальных клиентов

В работающей панели Avito возвращает `POST room status 403` с HTML nginx. Пользователь подтвердил, что браузер создаёт комнату. Сравнение с чистым v0.13.0 показало: `createRoom`, заголовки HTTP/WebSocket, парсинг комнат, cookies и формат комнат не изменены нашими патчами. Дифференциальный тест одного локального HTTP API на чистом и нашем пакетах подтвердил одинаковые запросы и ошибки для четырёх сценариев: успех/403 без cookies и с cookies. Причина отказа внешнего API не установлена; транспорт под него не переписывался.

Исправлены собственные ограничения совместимости: удалён добавленный нами тип `mixed` из allowlist share-формата; такая группа пропускается с пояснением, а остальные транспорты Multi продолжают экспортироваться. Обычный Multi больше не получает `--negotiate` при выключенной настройке строгого согласования; Direct/Script сохраняют обязательный Session. Шифрование, KDF и сетевые форматы не менялись.

Чистое ядро v0.13.0 собрано отдельно из исходного архива и использовано клиентом против сервера панели: передан 1 МиБ через Direct/SOCKS5. Оригинальный CLI проверяет также реальную ссылку сервера. Для восьми разрешённых transport types выполнены экспорт и импорт ссылок в обе стороны с оригинальным декодером; параметры транспорта, ключ и контекст совпадают. Это проверка общего кода ядра/формата Android и Windows, а не запуск APK или GUI приложения на устройстве.
