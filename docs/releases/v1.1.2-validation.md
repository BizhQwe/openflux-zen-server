# Валидация v1.1.2

Дата подготовки и проверки: 18–19 октября 2026. Базовая ревизия: `2c1ae60639d024f7d5263978a7fa5bf273cf090a`.

## Область проверки

Выборочная проверка внешнего HTTP-доступа, авторизации, сессий, Origin, браузерного вывода, загрузки/применения обновлений и клиентского формата. Это не полный аудит всех транспортов. Использованы рекомендации `security-audit` в guidance mode и независимые проверки исходников авторизации и совместимости.

Подтверждены регрессионными тестами и исправлены две гонки: выдача сессии по реквизитам, сменённым во время чтения запроса входа, и восстановление старых реквизитов ранее начатым запросом настроек. Проверены смена пароля/секретного пути и маршруты общих настроек, языка и профиля. Проверка Origin сохраняет native Bearer API и связывает браузерный запрос со схемой, адресом и портом.

До изменений bootstrap и автообновление исполняли скачанный установщик без сверки суммы. Добавлены SHA-256 с проверкой имени файла, приватный каталог, исключительное создание файлов, ограничения размера/времени и HTTPS-only redirects. Автообновление выбранного тега не переключается на latest при ошибке.

## Окружение исполнения

Пользователь предоставил отдельную Debian 13 VM и разрешил предварительно установить необходимые инструменты и зависимости. Go 1.26.9 загружен из официального источника и проверен по официальной SHA-256. PHP 8.4 и Node.js 20 установлены из Debian; govulncheck 1.9.0 подготовлен отдельно.

Исполнение кода проекта выполнялось без внешней сети: отдельный network namespace с loopback и dummy-интерфейсом `192.0.2.1/24`, без внешнего маршрута; bubblewrap с UID/GID 65534, без capabilities и доступа к host home, SSH-паролю или сокетам. Исходники, инструменты и предварительно загруженные Go-модули доступны только для чтения. Для сборки рядом с исходниками создана отдельная копия внутри scratch.

Окружение создано с нуля по allowlist: `PATH=/opt/go/bin:/usr/bin:/bin`, `HOME=/scratch/home`, временные файлы и кеши в `/scratch`, `GOTOOLCHAIN=local`, `GOPROXY=off`, `GOSUMDB=off`, `GOFLAGS=-mod=readonly`, `CGO_ENABLED=0`, `GOMAXPROCS=2`, `GOAMD64=v1`, `GOMEMLIMIT=512MiB`, `GOGC=50`, dummy USER/LOGNAME, `C.UTF-8`, UTC. Для межпроцессных тестов заданы только пути к двум локально собранным ядрам и `OPENFLUX_TEST_REQUIRE_PHP=1`.

Лимиты: CPU 180% двух ядер, RAM 1400 MiB, swap 256 MiB, 192 процесса, файл до 512 MiB, scratch на отдельной 6 GiB ext4, wall-clock до 1800 секунд на запуск; дочерние процессы завершаются вместе с группой. Независимый probe подтвердил отсутствие внешнего маршрута и запрет записи в `/src`, `/usr`, `/etc`.

## Выполненные проверки

- Go-тесты Web, CLI и Installer прошли, включая PHP integration и offline `systemd-analyze verify` с временным `/run/systemd` внутри scratch.
- Тесты пакетов Core прошли, кроме нагрузочного `TestFlowControlKeepsHandshakesQuickUnderBulk`, для которого не получен результат: его сценарий без flow control превысил cgroup-лимит RAM. Пакет PHPBox повторён с исключением только этого теста; остальные проверки прошли. Первые попытки с большей параллельностью также останавливала память; после перехода на `-p 1 -parallel 1` пройдены остальные пакеты.
- Два WebRTC-теста Script сначала не находили ICE candidate в среде только с loopback. После добавления dummy-интерфейса в изолированный namespace оба прошли; внешняя сеть не включалась.
- `go vet -p 1` прошёл для всех четырёх модулей.
- `node --test scripts/tests/*.test.cjs`: 11 passed, 0 failed, 0 skipped. Включены UI-регрессии и Linux bootstrap: верная/неверная/отсутствующая/чужая SHA-256, сохранение буквальных аргументов со спецсимволами и cleanup. HTTP-загрузки подменены fixture, реальный установщик не запускается.
- Тесты downloader проверили порчу содержимого, отсутствие/формат/имя/несколько SHA-256, существующий файл, пустую загрузку, лимиты без Content-Length, запрет HTTP downgrade и userinfo, недопустимые теги. Auth/Origin и downloader повторены с `-v` без пропусков.
- Linux helper проверен на dummy процессе и установщике: пути с пробелами/спецсимволами переданы буквально, старый процесс остановлен, приватный каталог удалён при exit 0 и exit 7. `TestUpdateHelperPreservesPathsAndCleansAfterInstaller` прошёл.
- Пройдены gofmt, синтаксический разбор PowerShell bootstrap/helper, shell bootstrap/helper, JS, сверка версий и `git diff --check`. Удалённая Mixed-подсказка отсутствует в HTML/JS/переводах.

Основные команды (пакеты запускались последовательно в описанном sandbox):

```sh

```

## Сборка релиза

Все семь установщиков собраны из новой копии исходников внутри scratch: `sh scripts/build.sh --all`, затем `sh scripts/package-release.sh --skip-build dist`. Для каждого из Windows amd64/arm64/386 и Linux amd64/arm64/386/armv7 независимо прочитан ZIP, встроенный в установщик: manifest содержит 1.1.2 и нужные OS/arch, SHA-256 всех трёх компонентов совпадает с manifest и соответствующими выходными бинарниками. Build info установщиков указывает Go 1.26.9. Агрегатный SHA256SUMS.txt проверен для семи установщиков и двух bootstrap.

Native Linux amd64: `--verify`, чистая установка без службы, повторная установка и обновление с опубликованной 1.1.1 прошли в scratch. Предыдущий установщик предварительно загружен и проверен по опубликованной SHA-256. После обновления сохранены username, passwordHash, passwordSalt, secretPath и dummy пользовательский файл; marker, Web и CLI показывают 1.1.2. Пути содержали пробелы и спецсимволы. Linux 386 также успешно исполнил `--verify`.

Перед переносом подтверждено побайтовое совпадение 604 входных файлов сборки с рабочим деревом; исключены изменённые после снимка release-документы, CI и новый отдельно выполненный тест helper. После завершения sandbox перенесены только 19 заранее перечисленных обычных файлов с одной hard link, без symlink, с лимитами размера и повторной проверкой identity/size. Суммарный размер: 183 982 960 bytes. После SSH-копирования на Windows SHA-256 каждого файла проверена повторно.

Для этого релиза используется комплект из указанного offline sandbox. Публикация commit/tag с `[skip ci]` пропускает GitHub push workflow по [штатному механизму GitHub](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/skip-workflow-runs): существующий workflow исполняет код с внешней сетью и не соответствует ограничению выбранного security-audit. Прохождение GitHub CI для 1.1.2 не заявляется.

## Ограничения размещения и обновления

Встроенный Localtunnel передаёт HTTP по обычному TCP от панели к relay (`publication/localtunnel.go`); внешний HTTPS заканчивается у relay. Этот участок не обеспечивает сквозную конфиденциальность от relay/наблюдателя сети. Изменение TCP на TLS без поддержки relay нарушит протокол. Для защиты этого участка нужен прямой HTTPS либо proxy с защищённым каналом до сервера. Протокол Localtunnel в 1.1.2 не менялся.

Windows bootstrap и helper разобраны синтаксически и скомпилированы для трёх архитектур в составе панели; фактическая установка, права ACL, Task Scheduler и завершение helper на Windows пока не проверены в отдельном OS sandbox. Linux systemd-unit проверен offline; обновление работающей службы systemd не запускалось. SHA-256 не заменяет доверие к издателю/GitHub. Проверка не доказывает отсутствие всех внешних уязвимостей.
